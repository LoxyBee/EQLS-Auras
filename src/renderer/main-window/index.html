            Spellbook detection

            Spellbook: Checking...

            Your character's own spellbook is used to resolve ambiguous buff messages (EQ reuses a lot of generic text across many different spells) down to whichever one you actually have. Read from your EQ install folder above.

            This is worth fixing. EverQuest reuses the same buff message across many different spells, and without your spellbook the app cannot tell which of them was yours - so it ignores them. On one recent session that was over 700 buff messages thrown away.

            The game does not write this file on its own. Type this in game, logged in on this character, and it only needs doing again when you scribe something new:

            /outputfile spellbook

            Which spells you currently have memorized is tracked separately and shown on the Buff Tracker page under "Detection status" - that's live gem state, not the spellbook file.

            About

            How auras work

            An aura is its own independent overlay window, with its own position, size, and buffs shown. Your auras are listed under "Overlay Auras" in the sidebar - click one to configure it, or use "+ Add aura" there to import a share code, add a premade aura, or build a custom one from scratch. "Self Buffs" is the built-in one and can't be deleted - it shows whatever you've marked "Overlay" on the Buff Tracker page's Known Buffs list. EQ needs to run in windowed or borderless-windowed mode (not exclusive fullscreen) for auras to be visible over it.

            How loadout profiles work

            If this server lets you swap between different multiclass "loadouts," swapping can change which spells you can actually cast without touching your spellbook file - which the app has no other way to detect. That means a "this ambiguous text means buff X" answer it learned under one loadout can quietly become wrong after you swap, with nothing telling you it happened.

            Loadout profiles fix this by giving each loadout its own separate memory of those answers. Switch profiles from the bar at the top of the app whenever you actually swap loadouts - nothing detects the swap automatically, so this is a manual habit, not something to expect the app to catch on its own. Add a profile with the + button; rename or delete one from the ⚙ "Manage" button next to it. Profiles also control which auras are on screen: an aura shows only while one of the profiles it belongs to is the active one, so switching profiles swaps your whole overlay layout along with the remembered answers. Set which profiles an aura belongs to from "Loadout profiles..." in its own settings. An aura with no profiles ticked shows on every profile.

            Where buff data comes from

            EverQuest has no universal "buff landed" message - every spell has its own flavor text, matched against ~3,300 real spells mined from the game's own data files. Much of that text is shared across spells (e.g. "You begin to regenerate." covers ~30 different regen buffs), so text alone often can't tell them apart - that's the problem the priority order below solves.

            The app also never reads log history - it starts at the bottom of the file and only watches new lines, for speed and to avoid re-triggering old chat/combat. That means state like your current gem slots, active buffs, and group are built live and start empty on each launch or restart - so an already-running ambiguous buff can get re-prompted once right after a restart.

            How a buff gets identified, most to least certain

            1. You just cast it by name. If the log just showed "You begin casting X" (or "You begin singing X" for bard songs), the very next landing line - even if that text is shared by other spells - safely confirms it, because we already know exactly what you cast.
            2. The landing text is unique to one buff. If only one spell in the whole database uses that exact wording, it's safe to trust with no other context at all. This is what catches instant clickies/AAs that produce no "begin casting" line to key off of.
            3. Ambiguous text, narrowed by what's currently memorized. If several spells share that landing text, but only one of them is sitting in one of your gem slots right now (tracked from "You have finished memorizing X." / "You forget X." lines), it's almost certainly that one - checked before the broader "ever scribed" check below because it's a stronger signal: you can only ever cast what's actually memorized at the moment, so it tells apart old ranks of a spell you leveled past from what you're actually using now, which "scribed at some point" alone can't. The one exception applies here too: if someone else in your group was just seen casting one of the candidates, it's not silently credited to you.
            4. Ambiguous text, narrowed by your spellbook. If the memorized check above didn't land on exactly one, but only one candidate is something you've ever scribed (regardless of gem slot), it's almost certainly that one - same "someone else just cast it" exception applies. This fallback exists because the memorized check only knows about gem swaps made since the app was opened - it has no memory of what was in your gems before that, so right after launch (before you've swapped anything) it has no memorized data to go on at all, and this broader check fills that gap.
            5. Ambiguous text during a "burst" (e.g. Quick Buff). Some abilities grant a dozen-plus buffs at once with no per-buff cast line at all - without this check, every one of those buffs would have no self-cast evidence whatsoever and would fall through to "probably someone else's" below, disappearing even though they're genuinely yours. Anything ambiguous that lands during that burst is presumed to be yours (you're the one who triggered it) - but which specific buff it was is still never guessed.
            6. Ambiguous text with no other signal. Most likely someone else's buff landing on you - by this point, a genuine self-cast would already have matched one of the signals above (named, unique, memorized, scribed, or a burst you triggered), so nothing left to check most likely means an ally's group/AoE spell landed on you too. Hidden by default, since tracking buffs cast on you by others is opt-in (Setup page) - this app is built around tracking your own buffs first.
            7. Still ambiguous? You get asked. If none of the above narrow it down to exactly one buff, the app doesn't guess - it queues the choice for you, shown in the Ambiguous Casts panel (Buff Tracker page) and in a small popup near the overlay, with a button for each real candidate. Whichever one you pick is remembered, so that exact landing text won't ask again - unless your group composition changes (group-targeted spells depend on who's actually in your group) or you clear it yourself from "View remembered choices."
